Replay an episode on the UR7e

Plays the joint angles of one episode on the arm. The dataset has to be a joint-angle LeRobot dataset (see How to make one below), on this NUC or on Hugging Face. The gripper is not replayed.

1

Dry run

No robot. Checks the joint limits, works out how long the replay takes at this speed, and draws the joint angles.

2

Check the robot

Read-only: connects to the IP and reads where the arm is. Never moves it. Compare the joints with the pendant of the robot you mean to move.

3

Run on the robot

Moves the arm slowly to the episode's start, then plays it. Workspace clear, hand on the e-stop. You will be asked to type RUN.

How to make a dataset you can replay

The robot needs joint angles. A normal Convert makes a camera + T265 pose dataset, which the robot cannot play. Use the Advanced options on the Convert tab instead.

  1. Record and Sync the dataset as usual. Converting for the robot needs the synced files on this NUC: a dataset that is only on Hugging Face cannot be converted again.
  2. Calibration: where was the robot base for this task? The joint angles are worked out from the robot base's position and orientation relative to where the T265 started. They come from config/config.json. If this task was recorded with the base somewhere else, do not edit that file (every other dataset uses it); make a copy for this task:
    cp config/config.json config/calib_<dataset>.json
    and change, in the copy: data_process_config.base_position (x, y, z in metres), data_process_config.base_orientation (roll, pitch, yaw in degrees) and ur7e_hardware.rest_joints_deg (this task's home pose, from the pendant). Then reload this page so Convert lists it.
  3. Convert tab → Advanced:
    • Output type: Robot replay: joint angles.
    • Calibration file: the copy from step 2 (or config.json if the base did not move).
    • FPS: leave empty ({{ S.DATASET_FPS }}). Only these episodes: optional.
    • Include the camera video: not needed by the robot; untick for a small dataset.
    • Push to Hugging Face (optional) uploads it to <user>/<dataset>_joint, separate from the camera dataset.
    Press Convert. The result is in <dataset>/lerobot_joint, and it shows up in the dataset list above.
  4. Check the Convert result. Each episode's line in the Convert log says reach=N/N … ok. An episode with VIOLATIONS (shown as a problem) has poses the arm cannot reach: the calibration is wrong, or the demo was recorded away from the calibrated spot. Do not replay it.
  5. Replay here: pick the dataset and episode, then do steps 1 → 2 → 3. Episode numbers here are the LeRobot episode index: 0 is the first converted episode, not recorded episode 0.
Safety, several robots, speed

Several robots with the same IP: the NUC connects to whichever one answers, which can be a different robot each time. Connect the NUC only to the robot you want (direct cable or its own switch), or give each robot its own IP on the pendant. Put only that robot in Remote Control; a UR in Local mode refuses outside programs. Step 2 shows the joints of the robot that answered: they must match its pendant.

Speed: playback is first slowed until it stays within the joint speed limits and the acceleration limit in config.json (joint_accel_limit_rad_s2), then slowed again by Speed. With the current limit a 20 s recording takes about 60 min at 0.1, 24 min at 0.25 and 6 min at 1.0. Above {{ S.REPLAY_FAST_SPEED }} you also type CONFIRM_FAST. To go faster, raise the acceleration limit after checking it against the pendant's safety settings.

Start pose: the move to the episode's start is very slow (0.03 rad/s × Speed). Jog the arm near the start (shown in step 2) with the pendant first.
